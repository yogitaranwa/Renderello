# Original-brief economics integration
14 November 2026, 09:12 IST. Offline implementation, not measured quality acceptance.

`python -m renderello.brief_economics --input records.json --output new-report.json`

Input uses existing `brief_acceptance.PlannedOutput`, `Attempt` and `Rating` fields under `plan`, `attempts`, `ratings`; `as_of` is an explicit ISO date. No live-generation, provider, payment or deployment operation exists. Output uses exclusive creation and will not replace a previous report. Missing evidence remains unknown.

Optional `price` requires currency, per_credit decimal string, rate_basis (`included_subscription_allocation`, `purchased_credit_pack`, `usage_invoice`), source_reference, observed_on and valid_through ISO dates and an explicit credit_system identifier. The top-level charge_credit_system must match it exactly. The declaration must cover every supplied attempt; split reports when providers or account/credit denominations differ. This is a caller declaration, not an automatic receipt-authentication step. No catalog or assumed marginal rate is substituted. An included-subscription allocation is not marginal price. The declared validity interval is checked against as_of; callers must actually verify current evidence. A URL/reference and typed rate are not authentication or proof of current vendor state.

Optional sale_price + sale_reference and other_cost_per_usable + other_cost_reference are explicit scenarios. Without each pair no contribution-margin scenario is produced. Include relevant infrastructure, storage, support and fees in the other-cost input; zero must be explicit and explained. The report is a per-usable-delivery scenario, not actual revenue, historical profit, a product price recommendation or an accounting/legal opinion. One consistent currency is used for all monetary scenario inputs; no FX is inferred.

All recorded charges remain in the numerator, including failed and retried attempts. A missing planned attempt, unresolved attempt status or missing charge suppresses total/unit monetary cost. All successful physical artifacts, including successful retries, must have complete recorded reviews before a publication-usable unit cost is shown. Known terminal failures need no invented image rating: their charges stay in the numerator, and original planned-slot acceptance remains separate. A successful retry artifact with no matching review keeps usable economics unknown even when every planned slot has a review. A missing end-to-end latency remains missing; submit request duration is not generation latency. First-try plans cannot substitute a later retry. Repeated output hashes do not pad distinct artifact denominators. Identical artifacts with conflicting usable/critical judgments are excluded from the usable denominator. The underlying coverage/quality evaluator retains its exact first-try gates and separate review provenance.

The primary distinction is between technical completed artifacts and reviewed usable artifacts. Even a mathematically positive scenario cannot set production_go or select a model. Best-quality/value fallback remain deferred until matched product fidelity and specialist review establish a viable choice. No software check is a photographic acceptance rate.

The legacy `costs.py` API still provides historical catalog projections; it does not supply the strict evidence fields for this path. Do not present its projections as observed charges. This module closes an implementation gap in joining the evidence, not the missing research/review/current-rate evidence itself.
